## 二、本章定位（考纲内容 / 知识框架 / 复习提示）

**考纲内容**（章首页 p236）：
- （一）传输层提供的服务——传输层的功能；传输层的寻址与端口；无连接服务与面向连接服务
- （二）UDP——UDP 数据报；UDP 检验
- （三）TCP——TCP 报文段；TCP 连接管理；TCP 可靠传输；TCP 流量控制与拥塞控制

**复习提示**（p236）：传输层是整个网络体系结构中的关键层次。要求掌握传输层在计算机网络中的功能、工作方式及原理等，掌握 UDP 及 TCP（如首部格式、可靠传输、流量控制、拥塞控制、连接管理等）。其中，**TCP 报文分析、连接管理、流量控制与拥塞控制机制，出选择题、综合题的概率均较大**，因此要将其工作原理透彻掌握，以便能在具体的题目中灵活运用。

**本章目标**：① 能手算拥塞窗口 cwnd 逐 RTT 演变（慢开始→拥塞避免→超时/三冗余 ACK 两分支）；② 能给报文段序列推 seq/ack 与可继续发送的数据量；③ 能默写三次握手/四次挥手各步标志位、序号、状态并算释放连接最短时间；④ 能手算 UDP 检验和（反码求和＋回卷）；⑤ 能对 TCP/IP 首部十六进制转储逐字段解析。

## 六、学习阶梯与陷阱（S/A 档）

> 证据等级：知识级推演（建模期归纳），非实测。

### 拥塞窗口 cwnd 逐轮演变（S · S-过程；CN-05-001~007）
- **L1** 认出四算法分工：慢开始（指数）、拥塞避免（线性）、快重传（3 冗余 ACK 立即重传）、快恢复（cwnd 减半不重置）
- **L2** 单段手算：给定 cwnd 与 ssthresh 初值，写出逐轮 cwnd 序列（1,2,4,8,16→17,18,…）
- **L3** 带分支手算：中途超时→ssthresh=cwnd/2、cwnd=1 重来；中途收 3 冗余 ACK→ssthresh=cwnd/2、cwnd=ssthresh 续线性
- **L4** 边界与陷阱：$2\times cwnd>ssthresh$ 时下一轮取 ssthresh（p257 注意框）；新门限=当前 cwnd 的一半而非旧门限一半；ssthresh 不得小于 2；cwnd=ssthresh 时常规转拥塞避免（参考疑难点 3@p278：超时=连 ACK 都回不来=拥塞重→cwnd 置 1；冗余 ACK=后续段已到达=拥塞轻→仅减半）
- **L5** 跨章串联：与 CN-05-009（rwnd）、CN-05-008（min）合出大题；与第 3 章 GBN/SR 窗口模型同构（档案"考得深"清单第 3 条）
- **预期变形**：给 cwnd 曲线图反推 ssthresh 与超时/冗余 ACK 发生的轮次；问"再经过 k 个 RTT 后 cwnd"（2009-42、2022-57）；慢开始期间每轮发送数据量求和（2016 综合：1+2+4+8）
- **陷阱**：把拥塞避免的"每轮+1"记成"每确认一段+1"（慢开始才是逐确认累加）；超时后忘把 ssthresh 减半；快恢复后误回慢开始

### 发送窗口 min[rwnd,cwnd] 与流量控制窗口演变（S · S-过程；CN-05-009、008，A：CN-05-021）
- **L1** 认出三窗口：rwnd（接收方缓存决定、窗口字段通知）、cwnd（网络拥塞决定）、发送窗口=min
- **L2** 单步手算：给 ack 与 rwnd 推"从 ack 起可连续发送的字节区间"（ack=501、rwnd=500→501~1000）
- **L3** 多轮手算：接收缓存只存不取→rwnd 每收 1KB 减 1KB；叠加慢开始 cwnd，每轮取 min（2016 综合题 14 全流程）
- **L4** 边界与陷阱：rwnd=0 后可超时重发**旧数据**但禁发新数据；零窗口通知丢失→死锁→持续计时器+零窗口探测报文段（CN-05-021）；窗口字段写的是"自己的接收窗口"不是拥塞窗口（题 09）
- **L5** 跨章串联：与第 3 章流量控制对比（CN-05-037：端到端 vs 相邻节点、动态 vs 固定）
- **预期变形**：给确认序列求"未收到新确认前还能发的序号范围/段数"（2021-56、2025-60）；求第一个完全窗口所需时间（题 39、综 07）
- **陷阱**：把 rwnd=0 误判为连接释放；漏 min 直接拿 cwnd 当发送窗口（2015-48 的 A 选项陷阱）

### TCP 序号与确认推进（S · S-过程；CN-05-010、011、013）
- **L1** 背出两条语义：seq=本报文段第一个数据字节的序号；ack=期望对方下一个字节的序号
- **L2** 单段手算：seq=301、长 100B→下一段从 401 起；收到 seq=501、200B→回 ack=701
- **L3** 多段失序手算：收到第 1、3 段缺第 2 段→ack=第 2 段序号（累积确认）；失序段缓存不丢弃
- **L4** 边界与陷阱：SYN/FIN 各耗 1 序号而"第三次握手不携数据不耗"；确认号 N 只保证 N-1 及以前收齐（题 11 的 C 选项口径）；"报文段 99 已收到"的说法错——序号属于字节
- **L5** 跨章串联：CN-05-014/016（握手挥手段序号）、与 CN 第 4 章 IP 分片（片偏移×8B）同为"给报文算字段"题型
- **预期变形**：由 SYN 序号与 FIN 序号差反推已发数据字节数（2020-53）；由确认号差求已收字节数（2012 综合题：16B）
- **陷阱**：把 FIN 段序号当成最后一个数据字节的序号（忘了 FIN 本身耗 1）；失序时误回失序段的序号而非第一个缺失字节序号

### 重传机制：超时 vs 冗余 ACK（S：CN-05-012；A：CN-05-020）
- **L1** 两种重传事件：超时（计时器到期）、3 个冗余 ACK（快重传）
- **L2** RTTS/RTO 关系判断：RTO 略大于 RTTS；太大→重传迟缓
- **L3** 冗余 ACK 计数：失序段每个到达都触发一次重复确认；t0 首次正常确认不计入冗余（2019-50 的 t3 时刻）
- **L4** 边界与陷阱：触发快重传时对同一报文段共收到 4 个确认（1 正常+3 冗余，p254 注意框）；TCP 重传机制=GBN 与 SR 的混合体（累积确认+缓存失序段+单点重传，SACK 增强）——疑难点 2@p277
- **L5** 跨章串联：与第 3 章 GBN"重传失序点起全部"对比出辨析题
- **预期变形**：给时序图问第几个时刻发生快重传；问"3 个冗余 ACK 后 cwnd 怎么变"（接 C-CN-05-02）
- **陷阱**：把正常确认计入 3 个冗余；认为 TCP 收到失序段会丢弃（那是 GBN）

### 三次握手（S · S-过程；CN-05-014、015、013）
- **L1** 默写三步报文：SYN=1 seq=x → SYN=1 ACK=1 seq=y ack=x+1 → ACK=1 seq=x+1 ack=y+1
- **L2** 状态机：CLOSED→SYN-SENT→（对端 SYN-RCVD）→ESTABLISHED×2；服务器先行 LISTEN
- **L3** 数字化：给初始序号 X/Y 写出三个报文的 seq/ack 完整值（2011-44、2019-51）
- **L4** 边界与陷阱：仅前两次 SYN=1；仅第一次 ACK=0；第三次握手可携数据不携则不耗序号→建连后首数据段 seq=x+1（题 27/28）；为什么不能两次握手——防已失效连接请求误建连（疑难点 4@p278）；为什么初始序号不能固定——防旧报文段串入新连接（疑难点 5@p278）
- **L5** 跨章串联：CN-05-018（握手时间：客户 1RTT、服务器 1.5RTT；2025-61 的 TCP 2RTT 服务时延）
- **预期变形**：给四次报文判合法性（SYN=0 ACK=0 的假报文）；握手与 TCP 段携数据合并考（2024-59：第三次握手段携 1000B）
- **陷阱**：第二次握手漏 SYN=1（只写 ACK）；把"SYN 消耗一个序号"记成"消耗两个"

### 四次挥手（S · S-过程；CN-05-016、017、019、018）
- **L1** 默写四步报文与状态：FIN-WAIT-1→FIN-WAIT-2→（对端 CLOSE-WAIT→LAST-ACK）→TIME-WAIT→2MSL→CLOSED
- **L2** 数字化：给 u/v/w 写出各步 seq/ack；w 可能大于 v（半关闭期间又发了数据）
- **L3** 时间手算：客户释放最短 1RTT+2MSL、服务器 1.5RTT；服务器无数据时同时回 ACK+FIN 跳过 CLOSE-WAIT（题 26=1.5RTT）
- **L4** 边界与陷阱：仅第一、三次 FIN=1；后三次 ACK=1；客户在收到对 FIN 的确认后进 FIN-WAIT-2，收到对方 FIN 回 ACK 后进 TIME-WAIT（2021-54）；半关闭=本方向已关仍可收（题 23）；FIN 段主流 OS 不允许携数据
- **L5** 跨章串联：CN-05-013（FIN 耗序号→数据量反推 2020-53）
- **预期变形**：给 RTT/MSL 求双方进 CLOSED 的最短时间（2022-58：1650ms/75ms；2024-59：60.04s）；判断某报文段中 seq/ack 的"一定为"断言（题 24：ack 必为 x+1、seq 不必为 y）
- **陷阱**：以为 FIN 后立即 CLOSED（漏 2MSL）；把服务器的 CLOSE-WAIT 当成必须停留的状态（最短时间情形可跳过）；2MSL 的作用记成"等待重传最后 ACK"之外漏"旧报文段消亡"

### TCP 报文段首部（A · S-结构/S-记忆；CN-05-023~027、022）
- **L1** 默写字段表：源/目的端口、seq、ack、数据偏移、保留、6 控制位、窗口、检验和、紧急指针、选项、填充
- **L2** 数据偏移换算：值×4B；5→20B、15→60B；十六进制转储中定位第 13 字节高 4 位（综 12）
- **L3** 首部×IP 首部联合解析：40B 转储拆 IP 头 20B+TCP 头 20B，读 TTL/标识/协议/序号/ack（2012 综合题）
- **L4** 边界与陷阱：TCP 首部无目标主机 IP（那是 IP 首部的）；TCP 伪首部协议字段=6（17 是 UDP）；窗口字段=自己的接收窗口；紧急指针仅 URG=1 有效且零窗口仍可发紧急数据；MSS 目的=避免 IP 分片、默认 536B（疑难点 1@p277）
- **L5** 跨章串联：CN 第 4 章 IPv4 分组格式（4.2.1）与 IP 分片——组合 C-CN-05-10
- **预期变形**：给十六进制首部求端口/序号/首部长度/连接状态（综 12、2012 综合）；问"TCP 有而 UDP 无的字段"（序号）
- **陷阱**：把数据偏移单位当 1B；把窗口字段当拥塞窗口；忽略选项后还有填充对齐

### UDP 数据报与检验（A · S-过程；CN-05-029~031、033）
- **L1** 默写 4 字段 8B 与长度最小值 8；UDP 优点五条
- **L2** 首部十六进制解析：0xF7210045002CE827→63265/69/44B/36B（综 04）
- **L3** 检验和手算：反码逐位求和→最高位进位回卷最低位→取反；接收方全 1 判定（2024-16 全过程）
- **L4** 边界与陷阱：伪首部 12B 不发送不递交但参与检验（含 IP 地址→NAT 改源 IP 后检验和须重算，2025-17）；长度字段不含伪首部；检验和结果恰为 0→填全 1；奇数字节补 0 仅计算用；UDP 无"首部长度"字段
- **L5** 跨章串联：CN 第 4 章 NAT（4.2.3）、ICMP 端口不可达（4.2.7）；UDP 分片×以太网 MTU（题 11/综 05）
- **预期变形**：UDP vs TCP 传输效率对比（2021-55：60% vs 37.5%）；跨网传输哪些字段不变（题 13：UDP 总长度、检验和、目的 IP）
- **陷阱**：把伪首部计入 UDP 长度字段；认为伪首部会传给对方；UDP 检验和算错后误做"请求重传"（实际直接丢弃）

### TCP vs UDP 全面对比（A · S-辨析；CN-05-028、032）
- **L1** 五维对照：连接性、端点数、可靠性、报文边界、首部开销
- **L2** 应用选型：DNS/DHCP/TFTP/RIP/SNMP→UDP；SMTP/TELNET/HTTP/FTP→TCP（表5.1）
- **L3** 说理题：为什么实时语音不宜 TCP（重传/拥塞控制引时延）、为什么 UDP 传文件会丢（综 02）
- **L4** 边界与陷阱：UDP 不保证可靠≠应用不可靠（可由应用层实现）；TCP 不支持广播多播；UDP 支持多播
- **L5** 跨章串联：第 6 章 DNS/HTTP/DHCP 的协议栈归属（C4 预埋）
- **预期变形**：给新应用场景选协议并说理由；判"UDP 面向报文所以不分片"（错——IP 层仍可能分片）
- **陷阱**：把"UDP 无拥塞控制"与"UDP 无流量控制"混为"UDP 无窗口"（rwnd 概念只在 TCP 考）；把 RIP/DHCP 记成 TCP
