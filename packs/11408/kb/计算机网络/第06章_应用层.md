## 二、本章定位（考纲内容 / 知识框架 / 复习提示）

**考纲内容**（章首页 p279）：
- （一）网络应用模型——客户/服务器模型；P2P 模型
- （二）域名系统 DNS——层次域名空间；域名服务器；域名解析过程
- （三）文件传输协议 FTP——FTP 的工作原理；控制连接与数据连接
- （四）电子邮件 E-mail——电子邮件系统的组成结构；电子邮件格式与 MIME；SMTP 与 POP3
- （五）万维网 WWW——WWW 的概念与组成结构；HTTP

**复习提示**（p279）：本章内容既可按选择题的形式考查，又可结合其他章节的内容出综合题。因此，**牢固掌握本章的几个典型应用层协议是关键**。我们生活中的很多网络应用都是建立在这些协议的基础上的，因此在学习时要注意联系实际，提高学习的兴趣，才会获得更好的学习效果。

**本章目标**：① 能对任意"非持续/持续（非流水线/流水线）× 并行连接 × DNS 解析方式"组合算出页面获取的 RTT 数或时间；② 能判定一次域名解析的查询方式、路径与报文次数；③ 能默写常用协议端口表并判定各协议的传输层服务（有连接/无连接）；④ 能给一封跨域邮件写出全程协议次序（SMTP×2 + POP3）并辨析 SMTP/POP3/IMAP/Web 邮件的方向与功能；⑤ 能叙述刚开机主机访问 Web 站点的完整通信过程（DHCP→DNS→ARP→TCP→HTTP）。

## 六、学习阶梯与陷阱（S/A 档）

> 证据等级：知识级推演（建模期归纳），非实测。

### HTTP/1.0 非持续连接 RTT 模型（S · S-结构）
- **L1** 记住结论：请求一个 Web 文档时间 = 文档传输时间 + 2×RTT（1 个 RTT 完成建连前两次握手、1 个 RTT 发请求并收响应）
- **L2** 单对象页面：从建 TCP 连接开始 2RTT；若"从发出 HTTP 请求报文开始"（TCP 已建）则只算 1RTT
- **L3** 多对象页面：每个网页元素单独建连接，n 个对象≈n×2RTT；浏览器支持并行连接时可同时建 n 条 TCP 并行取对象（1RTT 建连+1RTT 请求响应）
- **L4** 边界与陷阱：不支持并行的 2024 真题口径——每对象 2RTT、1 页+7 图=16RTT；对象总数要含基本 HTML 文件（1+100=101 个对象，不是 100 次）
- **L5** 跨章串联：TCP 三次握手第 3 次捎带 HTTP 请求的口径与第 5 章握手细节（CN-06-004）
- **预期变形**：给 RTT 数值+发送时延求总时间（综合题 02：150ms RTT+35ms gif 发送时延，非持续 t=300+335×10=3650ms）；问"至少"RTT 数（理想捎带）
- **陷阱**：把"HTTP 本身无连接"当成不用建 TCP 连接；漏算基本 HTML 文件这一个对象；并行与不支持并行两种口径混用

### HTTP/1.1 持续连接 RTT 计数（S · S-结构）
- **L1** 区分两种方式：非流水线（收完上一响应才发下一请求，每对象 1RTT）与流水线（连续发请求，全部引用对象共 1RTT）
- **L2** 标准页面（HTML+引用图像）：非流水线=1RTT 取页+每图像 1RTT；流水线=1RTT 取页+1RTT 取全部图像（2011 真题：rfc.html+5 幅 JPEG=6RTT）
- **L3** 起点口径变化：题目说"从发出 HTTP 请求报文开始"→TCP 已建，第 1RTT 就是取页（习题 12=2RTT）；说"从请求建立 TCP 连接开始"→加建连开销
- **L4** 边界与陷阱：必须先收到 HTML 才知道引用哪些图像——图像请求不能与取页并行（习题 12/13 的第 2RTT 才发图像请求）
- **L5** 跨章串联：流水线的理想 1RTT 会被 TCP 拥塞控制打破（CN-06-004）；持续连接定义（服务器发完响应仍保持连接）与 FTP 控制连接的"会话期保持"对照（CN-06-010）
- **预期变形**：HTTP/1.1 流水线+DNS 三级迭代求最多 RTT（习题 13：4+3=7）；持续连接下含发送时延的总时间（综合题 02：2150ms）
- **陷阱**：以为持续连接=所有对象 1 个 RTT（忽略"先收 HTML 才能发引用请求"）；非流水线当流水线算

### DNS 时长叠加 Web 访问的最短/最长时间（S · S-过程）
- **L1** 分清两段独立计时：DNS 解析段 + Web 传输段（建连 1RTT+请求响应 1RTT）
- **L2** 最短分支：本地缓存命中免 DNS（解析段 0 或按题意 1RTT）+TCP 建连取页 2RTT（2020 真题：2RTT=20ms）
- **L3** 最长分支：本地→根→顶级→权限三级迭代 3RTT（若缓存命中则仅 1RTT 返回）+2RTT 取页（2020 真题：5RTT=50ms；习题 13：4+3=7RTT）
- **L4** 边界与陷阱：DNS 段与 TCP 段的 RTT 数值可能不同（2020 真题 DNS RTT=10ms）；"主机→本地一律递归"不产生额外迭代 RTT；缓存命中时本地服务器直接回答、不再问根
- **L5** 跨章串联：TCP 建连 2RTT 口径来自第 5 章握手（前两次握手 1RTT+第三次握手捎带请求 1RTT）
- **预期变形**：把"最多/最少查询次数"换成"最多/最少 UDP 报文数"（4 查+4 答=8 个）；给出各级 RTT 不等的多级迭代
- **陷阱**：把三级迭代算成 4RTT（根→顶级→权限只有 3 步查询）；最短情形忘了缓存命中也要 1RTT 的题设口径（习题 13 口径：命中=1RTT）

### HTTP/1.1 × TCP 慢开始的逐 RTT 推演（S · S-过程）
- **L1** 认出题眼：数据量按 MSS 计+HTTP/1.1 持续连接+求"至少"时间——必须考虑初始 cwnd=1MSS
- **L2** 单轮口径：第 3 次握手捎带 HTTP 请求，发送窗口=cwnd（接收缓存足够大），每收到一确认 cwnd+1（慢开始）
- **L3** 多轮推演（2022 真题 18 标准形态）：第 1RTT 建连前两次握手→第 2RTT 捎带请求、发 1MSS（cwnd=1）→第 3RTT 确认并捎带图像请求、cwnd=2 发 2MSS→第 4RTT 确认、cwnd=4 发剩余 1MSS→共 4RTT=40ms
- **L4** 边界与陷阱：发送窗口受 cwnd 限制而非带宽；"忽略拥塞控制仅按应用层估算"会得出错误的小答案（6.6 疑难点 3 原话）
- **L5** 跨章串联：第 5 章 TCP 拥塞控制（慢开始逐轮 cwnd 表）同一套手算；2023 真题（C-CN-06-07）是 FTP 版本的同一推演
- **预期变形**：把对象改为 1MSS+3MSS 组合并问"至少 RTT 数"（4）；与 FTP 双连接、序号确认号组合出综合大题
- **陷阱**：漏掉"第 3 次握手捎带请求"的理想口径（否则加 1RTT）；cwnd 从 1 直接当 2 算

### 递归/迭代查询与四类域名服务器（A · S-辨析 / S-记忆）
- **L1** 背四类服务器：根（知道全部顶级服务器域名和 IP、13 个集群）、顶级（管二级域名）、权限（管特定区、必能解析其管辖主机）、本地（主机首先查询）
- **L2** 判定查询方式：看"谁替谁查"——本地代主机查=递归；根/顶级只指路不代查=迭代
- **L3** 返回路径推演：递归查询中结果由最初接受请求的本地服务器返回给主机；迭代查询中本地逐级问、逐级收"答案或指路"
- **L4** 边界与陷阱：主机→本地**一律**递归（与后续方式无关）；全递归给根负载过重、实际几乎不用；没有任何一台服务器含全部映射；根返回 TLD 服务器 IP 让本地再查=迭代（不是递归）
- **L5** 跨章串联：查询次数/报文数推演（CN-06-007）与 DNS 缓存（CN-06-008）
- **预期变形**：给"主机递归+本地迭代"或"全递归"组合问主机/本地各发几条查询（1/多条、1/1）；问根域名服务器管辖范围（顶级域，不是二级域）
- **陷阱**：把"根服务器保存全部主机映射"当真；权限服务器"总能解析"误推广到任意主机名

### 完整解析流程、报文计数与缓存（A · S-过程 / S-概念）
- **L1** 背八步流程与"最多 8 个 UDP 报文（4 查+4 答）"
- **L2** 按题设查询方式组合推演：全迭代规范域名 www.abc.xyz.com——最多 4 次查询（根→.com→xyz.com→abc.xyz.com）
- **L3** 缓存介入的口径：本地缓存命中=0 次对外查询、直接返回；主机端也有缓存、未命中才问本地服务器
- **L4** 边界与陷阱：TTL 到期自动失效清除（映射非永久）；"域名与 IP 一一对应"是假命题（CN-06-030）
- **L5** 跨章串联：与 CN-06-003 组合成时间题；DNS 用 UDP（CN-06-009）
- **预期变形**：问最少/最多 UDP 报文总数；问哪一级服务器返回最终答案（权限服务器）
- **陷阱**：把主机→本地的递归查询也计入"迭代次数"；缓存 TTL 当永久有效

### DNS 的传输层选择与服务归类（A · S-辨析）
- **L1** 记结论：DNS 用 UDP 53；FTP/SMTP/HTTP/POP3 用 TCP（20/21、25、80、110）
- **L2** 归类题口径："可使用传输层无连接服务的应用层协议"=DNS（2018 真题：FTP/SMTP/HTTP 都要可靠）
- **L3** 说理：DNS 请求可重复执行（重复请求返回相同结果、无害），不需要 TCP 的自动重传
- **L4** 边界与陷阱：DHCP 报文也只能用 UDP（分配到 IP 前无法用 TCP 建连，习题 12）；"HTTP 本身无连接"≠HTTP 用 UDP
- **L5** 跨章串联：第 5 章 UDP 特点（无连接、面向报文）
- **预期变形**：给出抓包的源/目的端口判协议（6.4.5@p300 综合题：目的端口 25→SMTP）；问某协议"直接封装"它的传输层协议（FTP-TCP、DNS-UDP、DHCP-UDP）
- **陷阱**：把 DNS 记成 TCP；把"熟知端口"用到客户端一侧

### FTP 双连接与状态维护（A · S-辨析 / S-概念）
- **L1** 背架构：控制连接（服务器 21、会话期全程保持、只传命令）+数据连接（服务器 20、按需建立传完即关、传文件内容）
- **L2** 判定某信息走哪条连接：登录/目录操作/中断指令→控制连接；LIST 文件列表与文件内容→数据连接
- **L3** PORT/PASV 两模式推演：PORT=服务器 20 主动连客户端指定端口；PASV=服务器随机开端口等客户端连；由客户端决定、默认 PORT
- **L4** 边界与陷阱：控制连接先建后拆（先于数据连接建立、晚于其释放）；20/21 指服务器端端口，客户端两端口号均自动分配；2017 真题错项"服务器与客户端的 TCP20 端口建立数据连接"方向说反；带外传送=控制信息与数据走不同逻辑信道（HTTP 属带内）
- **L5** 跨章串联：2023 综合真题把 FTP 双连接 × TCP 序号确认号 × cwnd 逐轮推演串成一道大题（C-CN-06-07）
- **预期变形**：给下载过程四步排序（建控制连接登录→告知随机端口→服务器 20 连过来→传完关闭）；问"控制连接持久、数据连接非持久"的对错
- **陷阱**：以为数据连接也全程保持；把客户端端口当成 20/21

### 电子邮件组成与协议方向（A · S-过程 / S-辨析）
- **L1** 背三大组成：用户代理 UA、邮件服务器、发送/读取协议
- **L2** 画推-推-拉：UA --SMTP--> 发送端服务器 --SMTP--> 接收端服务器 --POP3/IMAP--> 收件人（2012 真题三段答案）
- **L3** 方向判别：SMTP 只推不拉（UA→服务器、服务器→服务器）；POP3/IMAP/HTTP 只拉不推（读取）
- **L4** 边界与陷阱：SMTP 不使用中间服务器中转（TCP 直连两端服务器）；POP3 的两种模式（下载并保留/下载并删除）与"一条 TCP 连接收多封邮件"；Web 邮件浏览器↔服务器用 HTTP、仅服务器间用 SMTP；From 与发送时间由系统自动生成、To/Subject 由发件人填
- **L5** 跨章串联：SMTP/POP3 端口（CN-06-028）与 TCP 依据（CN-06-009）
- **预期变形**：给三段链路问每段协议；问"哪个协议不能接收邮件"（SMTP）；问 POP3 的传输层服务（有连接可靠）
- **陷阱**：把 IMAP 当"下载后删除"（那是 POP3 模式）；把 Web 邮件全程当 SMTP

### MIME 与 POP3/IMAP 细节（A · S-概念 / S-记忆）
- **L1** MIME 动因一句话：SMTP 只支持 7 位 ASCII
- **L2** 机制辨析：MIME 不修改不取代 SMTP——发送端编码为 ASCII→SMTP 传→接收端解码
- **L3** POP3 双模式与应用：下载并保留 vs 下载并删除；IMAP 支持服务器端文件夹操作与选择性获取（只取首部/某部分）
- **L4** 边界与陷阱：2018 真题"无须转换即可由 SMTP 直接传输的内容=ASCII 文本"；MIME 新增 5 个首部字段名
- **L5** 跨章串联：CN-06-020（读取协议归类）
- **预期变形**：给"中文邮件/图片附件"问走什么编码路径；问 IMAP 服务器是否需维护会话状态（是）
- **陷阱**：把 MIME 当独立传输协议；把 IMAP 当 POP3 的别名

### HTTP 特点、Cookie 与报文结构（A · S-概念 / S-记忆）
- **L1** 背三特点：TCP 可靠、本身无连接、无状态；背报文三段结构（开始行/首部行/实体主体，空行分隔）
- **L2** 判定类题：请求行 vs 状态行字段次序（方法 URL 版本 / 版本 状态码 短语）；HEAD 不返回请求对象
- **L3** Cookie 流程复述：首次访问→服务器生成识别码+后端数据库记录→Set-cookie 响应首部→浏览器存本地→再次访问请求自动带 Cookie 首部
- **L4** 边界与陷阱：Cookie 存在客户端（习题 09 错项）；请求报文含 Cookie 表示曾访问过（2015 真题 17）；Connection:Close=非持续、Keep-Alive=持续；"无状态"与 Cookie 的关系=Cookie 给无状态的 HTTP 补状态
- **L5** 跨章串联：CN-06-022 与 CN-06-012（FTP 有状态）构成对照；报文均为 ASCII 文本与 SMTP 相同口径
- **预期变形**：给一段真实请求报文逐行判读（GET 行、Host、Connection、Cookie）；问响应状态码含义（202/400/404）
- **陷阱**：把"HTTP 本身无连接"理解成传输层用 UDP；把状态行写成"方法 URL 版本"

### Web 访问全流程与协议栈（A · S-过程）
- **L1** 背八事件次序：URL→DNS→IP→TCP→HTTP 请求→HTTP 响应→释放→显示
- **L2** 协议栈归类：应用层 DHCP/DNS/HTTP；传输层 UDP+TCP；网际层 IP+ARP；链路层 CSMA/CD 或 PPP
- **L3** 刚开机完整过程（6.6 疑难点 4）：DHCP 获取配置（UDP→IP→MAC 帧）→DNS 解析（同子网 ARP 解析 DNS 服务器；跨子网 ARP 默认网关）→TCP 80→HTTP GET→引用资源逐个请求→四次挥手
- **L4** 边界与陷阱：2021 真题封装链=DNS 报文→UDP 数据报→IP 数据报→以太网帧；ARP 请求帧目的 MAC=FF-FF-FF-FF-FF-FF（广播）；交换机不记录未主动发数的 H2；跨子网时主机 ARP 的是**默认网关**的 MAC 而非远端服务器
- **L5** 跨章串联：第 4 章 ARP/DHCP、第 3 章以太网帧（C4 形态，C-CN-06-11）
- **预期变形**：给拓扑问交换表内容与 H2 收帧数（2021 真题：3 条表项、2 个帧）；问 NAT 路由器转发时改哪些字段（源 IP→全球 IP、TTL-1、重算首部检验和、超 MTU 改总长度/标志/片偏移）
- **陷阱**：把 ARP 广播帧当成单播；把"访问 Web 不可能用到的协议"答成 ARP/PPP（应是 SMTP）

### 端口表与熟知/临时端口（A · S-记忆 / S-概念）
- **L1** 背表 6.2：FTP 20/21、TELNET 23、SMTP 25、DNS 53、TFTP 69、HTTP 80、POP3 110、SNMP 161
- **L2** 判定端口归属：全部指**服务器端**熟知端口；客户端用系统自动分配的临时端口
- **L3** 端到端连接的唯一标识=（服务器熟知端口+客户临时端口）这一对端口号
- **L4** 边界与陷阱：FTP 数据连接在 PASV 模式下服务器用随机端口（20 仅 PORT 模式默认）；TFTP（UDP 69）与 FTP（TCP 20/21）是不同协议
- **L5** 跨章串联：第 5 章端口与套接字定义
- **预期变形**：给十六进制端口字段（0x0019=25→SMTP）判协议；问"客户端默认不使用 20"的正误（正确）
- **陷阱**：把 20 端口安到客户端；SNMP 记成 TCP
