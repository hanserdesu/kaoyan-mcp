## 六、学习阶梯与陷阱（S/A 档）

> 证据等级：知识级推演（建模期归纳），非实测。本章无独立「常见问题和易混淆知识点」节，陷阱取证以 4.2.5 答案与解析（p131-134）与归纳总结（p135）为准。

### KMP 算法原理与不回溯机制（S · S-概念）
- **L1** 能说出三个角色：暴力匹配为什么慢（主串指针回溯 → 大量重复比较）、KMP 改进点（主串指针不回溯）、实现手段（预计算 next 数组）
- **L2** 给定已匹配前缀，判断其后缀与模式串前缀是否相等，指出模式串应滑动到的对齐位置
- **L3** 换一个模式串（含重复字符 / 无重复字符）重新分析滑动逻辑；解释"对齐部分无须重新比较"
- **L4** 边界与陷阱：已匹配部分不存在相等前后缀（PM=0）时滑动最大——模式串首字符对齐失配位；PM 表与 next 数组不是同一个东西（转换关系见 DS-04-004）（参考 4.2.5 解析 p131-132）
- **L5** 跨章串联：与 DS-04-011（复杂度对比）互为因果；朴素算法过程（DS-04-010）是理解本原理的对照组
- **预期变形**：给一段匹配过程截图问"下一步 i、j 各是多少"（2015 问法）；问"KMP 在什么场合优势明显"（答案：存在大量部分匹配时）
- **陷阱**：把"主串指针不回溯"说成"指针不移动"——i 不回退但每轮可能随匹配成功后移；把 PM 值当成 next 值直接用

### 部分匹配值（PM）手算（S · S-过程）
- **L1** 背熟定义：前缀=除最后一个字符外的所有头部子串；后缀=除第一个字符外的所有尾部子串；部分匹配值=最长相等前后缀的长度
- **L2** 手算 5-6 位模式串的 PM 表（'ababa'→00123、'abcac'→00010）
- **L3** 手算含重复字符的长模式串（'ababaaababaa'→0 0 1 2 3 1 1 2 3 4 5 6，p131 解析 06 原例）
- **L4** 边界与陷阱：第 1 位恒为 0（前后缀交集必空）；"最长相等前后缀"允许前缀与后缀重叠（'ababa' 的 3 = 前缀 'aba' 与后缀 'aba' 共用中间字符）（参考 4.2.5 解析 p131）
- **L5** 跨章串联：PM 表本身不直接进答案，下一步必须会转 next（DS-04-004）或直接用右滑公式（右滑位数=已匹配字符数−对应 PM 值）
- **预期变形**：给新串求 PM 后直接问"失配时右滑几位"；PM 与 next 两列并排让选正确的 next 行
- **陷阱**：把"前后缀相等"求成"前后缀任意公共子串"（求的是完整首尾对齐，不是子串）；忽略重叠允许条件

### next 数组手算（1 起编号）（S · S-过程）
- **L1** 背固定规则：next[1]=0、next[2]=1
- **L2** 用分界线法手算 5 位模式串（'abcac'→0 1 1 1 2）：失配位前画线，右移模式串找首尾对齐或完全跨线
- **L3** 用递推法手算 6-9 位模式串（p134 综合题 02 全过程：'aabaac'→0 1 2 1 2 3，j=4 时 k 沿 next[k] 链回退到 0）
- **L4** 边界与陷阱：递推时比较的是 S[j−1] 与 S[k]（p133 解析原话），不是 S[j]；k=0 时直接置 next[j]=1 而不是继续回退；0 起编号的题目 next 整体减 1（DS-04-009）（参考 4.2.5 解析 p133-134）
- **L5** 跨章串联：next 是 nextval（DS-04-007）与匹配模拟（DS-04-008）的直接输入——链条首环
- **预期变形**：给两个长度 6-8 的模式串分别求 next 再比较某一位；题干直接给 0 起编号（必须转换口径）
- **陷阱**：混用两种编号口径（1 起的 next[1]=0 与 0 起的 next[0]=−1 写进同一张表）；递推比较对象找错位

### next 与 PM 的转换 / 编号起点（A · S-概念）
- **L1** 记住结论：next 数组 = PM 表右移一位再整体加 1（首空补 0、末位舍去）
- **L2** 给 PM 表写出 next（1 起）；给 next 表反推 PM
- **L3** 遇 0 起编号题：next 整体减 1（首项 −1）；nextval 口径滑动距离=j−nextval[j]（0 起）
- **L4** 陷阱：p131 解析 06 先按 1 起得 −1 开头的 next，再因选项 next[1]=0 整体加 1——先看清题目采用的口径再落笔；PM 末位永远用不上（它服务于"下一个字符"）（参考 4.2.5 解析 p131、p133 解析 10）
- **L5** 跨章串联：本原子是 C-DS-04-01/02 的中间转换环节
- **预期变形**：同一模式串分别按 1 起与 0 起给四个 next 选项（两两只差常数 1）
- **陷阱**：右移后忘补首项；对 0 起题目套用 1 起结论

### next 递推公式（三分段定义与两分支递推）（S · S-过程）
- **L1** 背三分段：j=1 时 0；k 集合 {k | 1<k<j 且 'p1..p(k-1)'='p(j-k+1)..p(j-1)'} 非空取 max；否则 1
- **L2** 能回答综合题 01 三小问（p133）：next[1]=0 表示首字符失配时右滑一位；取 max{k} 是因为 j−k（右滑距离）要最小、k 最大为 j−1；其他情况=最坏时模式串第 1 个字符与主串当前字符比较
- **L3** 用两分支递推填 6 位以上 next：p(k)=p(j) → next[j+1]=next[j]+1；不等 → k=next[next…[k]] 沿链回退（p134 'aabaac' j=4 的完整回退链 2→1→0）
- **L4** 边界与陷阱：回退链逐级缩小相等前后缀长度，直到不等或 k=0；p133 综合题 02 递推比较的是 S[j−1] 与 S[k]，错位则全链错（参考 4.2.5 解析 p133-134）
- **L5** 跨章串联：与 DS-04-017（代码段）同构——递推分支即 get_next 的 if/else
- **预期变形**：给出 5 位 next 值求第 6、7 位（图4.4 p128 原题型：next[7]=1、next[8]=2、next[9]=3）
- **陷阱**：把"集合为空"与"k=1"混为一谈（集合非空时 k>1，空时才落 1）；递推时跳过了"不存在更长相等前后缀"的验证

### 失配时的指针变化 / 首字符失配边界（S · S-概念 + A 边界，DS-04-006 + DS-04-012）
- **L1** 背结论：失配时 i 不变、j=next[j]；j=0 时 i、j 同时加 1
- **L2** 给定 next 表和失配位置 (i,j)，写出下一轮比较的 (i,j)（2015 原题：i=j=5 失配 → i=5、j=next[5]=2，0 起）
- **L3** 连续失配的指针轨迹模拟：j 逐级沿 next 跳，直到匹配或 j=0 触发 i+1
- **L4** 边界与陷阱：模式串第 1 个字符失配=已匹配字符数 0 的特殊情况（p126）——整体右移一位、从主串下一位置重新开始，对应代码 j=0 分支；"i 不会变小"≠"i 不变"（p130 题 02 与 05 的选项差异）（参考 4.2.5 解析 p131-133）
- **L5** 跨章串联：指针规则是 C-DS-04-03（比较次数）与 C-DS-04-08（同族干扰）的核心格点
- **预期变形**：问"KMP 中主串指针的特点"（不会变小）；问"j=0 的语义"；给 i、j 初值与 next 表让写出完整匹配轨迹
- **陷阱**：把 next[j] 当成滑动距离（它是新的 j 位置，滑动距离要另算）；漏掉 j=0 时 i 也要加 1

### nextval 数组手算（S · S-过程）
- **L1** 背修正动机：p(j)=p(next[j)] 时，用与 p(j) 相同的字符去和已知不等的 s(i) 比较必然再失配（p129 原文"不应出现 p(j)=p(next[j)]"）
- **L2** 背递推规则：nextval[1]=0；一般位：T.ch[i]==T.ch[j] 时 nextval[i]=nextval[j]，否则 nextval[i]=j（j 为当前 next 值）
- **L3** 手算完整 nextval 表（'aaaab'：next 0 1 2 3 4 → nextval 0 0 0 0 4；'aabaab' 0 起：nextval=−1 −1 1 −1 −1 1，p133 解析 12）
- **L4** 边界与陷阱：必须先有正确的 next 才能修 nextval——链条顺序不可颠倒；0 起题目 nextval 首项是 −1（p132 解析 09 表）（参考 4.2.5 解析 p132-133）
- **L5** 跨章串联：nextval 是比较次数对比题（C-DS-04-07）与 2024 真题的直接考点
- **预期变形**：2024 问法——"失配时向右滑动的最长距离"=max{ j−nextval[j] }，逐位算距离取最大（'aabaab' 在 j=4 处 = 5）；给 next 与 nextval 两行让挑正确的 nextval 行
- **陷阱**：把 nextval 直接当成 next 用（滑动距离公式不同）；修正条件漏判"字符相等"这一前提

### KMP 匹配过程模拟与比较次数（S · S-过程）
- **L1** 能按趟组织一次匹配：每趟从模式串某位开始连续比较，记下每趟比较次数
- **L2** 手算一个 4-6 趟的完整匹配（p132 解析 07：第一趟 3 次、第二趟 1 次、第三趟 1 次、第四趟 4 次，总计 9）
- **L3** 用 nextval 版本重算同一题并解释节省（同题 nextval 7 次：nextval[3]=0 跳过两次注定失败的比较）
- **L4** 边界与陷阱：j=0 跳转的那一次不算"字符比较"（p132 解析 07 第三趟 1 次的说法）；"第一趟连续比较 6 次后失配"的数法（2019 原题）要含最后一次失配比较本身（参考 4.2.5 解析 p132-133）
- **L5** 跨章串联：与第 1 章"最好/最坏/平均复杂度"口径衔接；2019 真题即本原子原题
- **预期变形**：2019 问法——给主串模式串求"单个字符间的比较总次数"；换 nextval 再问一次；问第 k 趟从主串哪个位置开始
- **陷阱**：漏数失配那一次比较；趟数与次数混淆（趟数≠总次数）

### 编号起点口径（0 起 vs 1 起）（A · S-概念，DS-04-009 专项）
- **L1** 背差异：1 起 next[1]=0；0 起 next[0]=−1（整体减 1）
- **L2** 给题目先判口径：题干出现"i=j=5 失配""编号 0..5"即 0 起（p133 解析 10 明示）
- **L3** 两种口径各算一遍同一模式串并互相验证（差常数 1）
- **L4** 陷阱：nextval 的滑动距离公式 j−nextval[j] 只在 0 起口径下成立（p132 解析 09、p133 解析 12 均按 0 起）（参考 4.2.5 解析 p132-133）
- **L5** 跨章串联：与第 3 章特殊矩阵压缩存储"下标从 0/1 开始"陷阱同型
- **预期变形**：四个选项两套口径各两个；题干故意不给口径让从"i=j=5"自行判断
- **陷阱**：全书正文以 1 起讲解，真题近年用 0 起——死记一套数字必错

### 朴素模式匹配过程与回退规则（A · S-过程）
- **L1** 背失配回退：i=i−j+2（回到本次匹配起点的下一位）、j=1
- **L2** 模拟 2-3 趟朴素匹配（p124 图4.2 前两趟）
- **L3** 完整模拟 6 趟并数比较次数；解释最坏实例（'00000001' 类主串）为何每趟都比较到模式串末位才发现失配
- **L4** 边界与陷阱：最多 n−m+1 趟、每趟最多 m 次、最坏 O(nm)；成功返回 i−T.length（起点位置）而不是 i（参考 4.2.1 p123 代码与 p124 分析）
- **L5** 跨章串联：作为 KMP 的对照基线（C-DS-04-05 链首）
- **预期变形**：问第 k 趟主串从哪个位置开始比较；问最坏情况总比较次数（40×7=280 一类）
- **陷阱**：回退公式写成 i=i−j+1（少退一位）；把返回值当成当前 i

### 复杂度对比 O(nm) vs O(m+n)（A · S-结构）
- **L1** 背两个阶：朴素 O(nm)、KMP O(m+n)
- **L2** 会推导朴素最坏趟数×每趟次数 = (n−m+1)·m
- **L3** 解释"KMP 仅在大量部分匹配时显著优于暴力，一般情况朴素平均接近 O(m+n)"（p129 原文）
- **L4** 陷阱：认为 KMP 总是远快于朴素（一般情况差距不大）；把 next 数组构造的 O(m) 忘进总复杂度（参考 4.2.3 p129）
- **L5** 跨章串联：与 DS-01-002（第 1 章复杂度分析）同源；C-DS-04-10 的结论格
- **预期变形**：双空题同时问朴素与 KMP 的阶（p130 题 03 原型：C、D）
- **陷阱**：把 O(m+n) 写成 O(n)（丢掉构造 next 的 m）

### KMP 关键代码（get_next / Index_KMP / get_nextval）（S · S-算法）
- **L1（思想层）** 能用一句话分别说清三个函数：get_next 预计算跳转表；Index_KMP 用表做匹配（i 不回溯、j=next[j]）；get_nextval 在预计算时顺带做"相同字符"修正
- **L2（代码层）** 默写 Index_KMP 主循环四要素：循环条件 i≤S.length 且 j≤T.length；相等或 j==0 时 ++i;++j；否则 j=next[j]；j>T.length 返回 i−T.length
- **L3（代码层）** 默写 get_next 与 get_nextval 的差异行：next[i]=j vs （相等且字符同则 nextval[i]=nextval[j]，否则 nextval[i]=j）
- **L4（边界）** j==0 分支必须 i、j 同时加 1；返回值区分 i−T.length（成功）与 0（失败）（参考 4.2.2 p128 与 4.2.3 p129 代码框）
- **L5** 跨章串联：与第 2 章顺序表/链表算法题的"思想+代码"双段评分结构同构（C-DS-04-04）
- **预期变形**：综合题先写思想再补代码（2024 前的老考法，书注统考应不会考 KMP 算法题，按储备处理）；给挖空的 KMP 代码让补分支
- **陷阱**：get_nextval 忘了"字符相等才继承 nextval[j]"这一条件；把两个返回值写反

### 串与线性表的关系 / 最小操作子集（B · S-记忆，DS-04-014/013 形式口测层）
- **L1** 背结论：逻辑结构极相似、数据对象限定为字符集；操作单位差异=单元素 vs 子串
- **L2** 背最小操作子集五种：StrAssign、StrCompare、StrLength、Concat、SubString
- **L3** 解释"其余操作可由最小子集实现"（如 Index 可由 SubString+StrCompare 循环实现）
- **L4** 陷阱：Index 定位失败返 0；StrCompare 返回值三态（>0 / =0 / <0）（参考 4.1.2 p122）
- **L5** 跨章串联：与第 2 章线性表抽象操作对比（同构不同型）
- **预期变形**：判断"串的基本操作以单个字符为单位"（错，以子串为单位）
- **陷阱**：把 ClearString/DestroyString 也算进最小子集（明确排除，p122 原文）
